## Sync/blocking conditions observed

1. **NPS Sofia / LGPD modals** — não apareceram com storageState ativo (já tratados pelo `dismissCommonModals` se aparecerem em sessão nova).
2. **Click no label do switch** (e não no input) — input chakra é `clip: rect(0,0,0,0); width: 1px`; click direto no input falha actionability. Sempre usar `label.chakra-switch` que envolve o input.
3. **Após click**, o checkbox state muda imediatamente quando painel não tem associação — sem chamada a API extra que precise de wait. Para painel associado, hipótese (não validada live por falta de seed) é que o modal abre antes do estado mudar.
4. **Reload (`page.reload()`)** preserva storageState — a sessão continua válida e a listagem recarrega normalmente.

## Conflito TC1 ↔ TC2 — estratégia adotada (revisada 2026-05-06)

- **Decisão atual**: **auto-seed por spec** (`beforeAll`/`afterAll`). Cada
  spec cria seu próprio painel via UI (`createPanel`) com nome
  worker-isolated `Painel QA Teste TC{N} w{workerIndex}-{ts}` e deleta no
  cleanup (`deletePanelByNameSafe` — não falha se a row não existir).
- **Por quê auto-seed em vez de seed externo**: elimina dependência de dado
  pré-existente, permite execução paralela sem colisão, e cobre o flow de
  CRUD do painel como side-effect (criação via form `/panels/new` e
  exclusão via modal de confirmação `[role="alertdialog"]`).
- **Estratégia anterior (afterEach + ensureActive)**: substituída — não
  resolvia o problema raiz (seed ausente) e introduzia falha em cascata
  quando o painel não existia.
